# Demo Video MCP — fleet-powered intro video pipeline

**Status:** PROPOSED (refined 2026-07-29)
**Priority:** P1

## Problem

50+ webapp repos, zero promo videos. Producing one manually is ~2h of OBS + audio sync + editing. The fleet already owns every tool needed — they're just not wired together.

## Wider problem: FOSS repos have no demo videos

Most open-source repos ship README screenshots at best. Only well-funded projects (big corps, well-known startups) have intro videos — because they employ a human video person. OSS maintainers don't have that luxury. This pipeline aims to close that gap: **any repo can have a narrated, subtitled intro video generated by its own tooling**, not by a human with Final Cut.

If it works for the fleet, it works for any FOSS repo. The tooling is CI-compatible and costs nothing beyond the compute.

## The hard problem: two completely different capture modes

~20 fleet repos have webapps that Playwright can capture headless. The other ~30 show their value **inside a native desktop host app** — Blender, Resonite, DaVinci Resolve, VRoid Studio, Unity, GIMP, KiCad, Mixxx, etc. A webapp-only pipeline covers half the fleet at best.

The unified solution: **dual-mode recording in the same narration script**. Script steps can capture webapp pages OR desktop windows interchangeably. The compose stage stitches both into one timeline.

```
narration.yaml step:                              captured by:
  - action: goto                    ──→ Playwright (headless Chromium)
    url: /dashboard

  - action: capture_window          ──→ PyWinAuto + screenshot (real desktop)
    window: "Resonite"
    region: "viewport"
    pre_steps:                      ──→ keyboard/mouse commands before capture
      - click: 640, 480
      - key: "F5"

  - action: click                   ──→ Playwright (within webapp)
    target: "[data-testid='export-btn']"

  - action: capture_window          ──→ PyWinAuto (back to desktop)
    window: "Save As"
    pre_steps:
      - type: "output.mp4"
      - key: "Enter"
```

The compose stage receives a mixed list of `.webm` segments (Playwright) and `.png`/`.webm` segments (desktop screenshots, optionally compiled to `.webm` with pan/zoom) and concatenates them with crossfades.

## Architecture

### demo-vid-mcp tools

| Tool | What it does |
|------|-------------|
| `demo_vid_generate(repo)` | Full pipeline: all stages, max parallelism |
| `demo_vid_refine(video_id, feedback)` | LLM re-times, re-narrates, re-renders |
| `demo_vid_list(repo?)` | List produced videos (local + depot) |
| `demo_vid_script_draft(repo)` | LLM reads README + app routes → drafts narration.yaml |
| `demo_vid_script_validate(repo)` | Check selectors resolve, voice available, timing sane |
| `demo_vid_stage(video_id, stage)` | Re-run a single stage (record, voiceover, title, compose) |
| `demo_vid_batch()` | Generate videos for all repos without one |

### Narration script — dual-mode actions

```yaml
title: "Resonite MCP — AI worlds from Claude"
duration_target: 90
voice: "heart"
title_style:
  type: "blender"
  template: "fleet-intro"
  duration: 5
music:
  source: "stems"
  track: "ambient-calm"
  volume: 0.3
steps:
  # ── Webapp segment ──
  - action: goto
    url: "/"
    wait: 3
    say: "Resonite MCP gives Claude control over your Resonite worlds."

  # ── Desktop segment (capture the host app) ──
  - action: capture_window
    window: "Resonite"
    region: "viewport"              # "full" | "viewport" | {x,y,w,h}
    pre_steps:                      # prepare the scene before capture
      - click: 100, 200            # click coordinates (within window)
      - key: "F5"                  # press key
      - wait: 2                    # let scene settle
    wait: 4
    say: "Spawn avatars, place objects, script behaviours — all from a conversation."

  # ── Back to webapp ──
  - action: goto
    url: "/worlds"
    wait: 2
    say: "Browse your worlds, inspect sessions, or launch new ones."

  # ── Desktop segment again ──
  - action: capture_window
    window: "Resonite"
    pre_steps:
      - type: "avatar nekomimi-chan"   # type into focused field
      - key: "Enter"
      - wait: 3                         # wait for avatar to load
    wait: 5
    say: "This is nekomimi-chan — a fully rigged avatar deployed from Claude. No manual import, no Unity."

  - action: end
    say: "Resonite MCP. Open source. Try it today."
```

### Capture mode reference

| action | Mode | Tool | Captures | Platform |
|--------|------|------|----------|----------|
| `goto` | Webapp | Playwright | Browser page at URL | All (headless) |
| `click` | Webapp | Playwright | Click on CSS/data-testid target | All (headless) |
| `type` | Webapp | Playwright | Type into form field | All (headless) |
| `capture_window` | Desktop | PyWinAuto + `cua_automation_visual` | Named window region | Windows |
| `click_window` | Desktop | PyWinAuto | Click at coordinates in window | Windows |
| `type_window` | Desktop | PyWinAuto | Send keys to window | Windows |
| `key` | Both | PyWinAuto / Playwright | Single key press | Both |

Desktop mode uses `cua_automation_visual(screenshot)` under the hood: locate window by title, optionally activate it, take a region screenshot, save as PNG frame. A sequence of frames with pan/zoom becomes a `.webm` segment.

### Pipeline stages (updated)

```
1. VALIDATE ── script parses, all selectors/window titles resolve, fleet services reachable
       │
2. VOICEOVER ── speech-mcp: TTS per say: segment → concatenated .wav
       │
3. TITLE ART ── blender-mcp or gimp-mcp or plain text fallback
       │
4. RECORD ── FOR each step in order:
       │        ├─ webapp step → Playwright (headless, continues from last step)
       │        ├─ desktop step → PyWinAuto (screenshot sequence, compiled to .webm)
       │        └─ all segments stored in ordered list
       │      Runs CONCURRENT with voiceover + title art
       │
5. COMPOSE ── davinci-resolve-mcp or FFmpeg:
       │      Ordered segments + .wav + title card + subtitles → .mp4
       │
6. POST ── vfx-mcp transitions, stems-mcp music, sfx-mcp sound effects
       │
7. DEPOT ── depot-mcp: store .mp4 + metadata
```

### Desktop capture details

Desktop captures use one of three methods, chosen by what's available:

| Method | What it captures | How | Deps | Quality |
|--------|-----------------|-----|------|---------|
| **PyWinAuto** (`cua_*` tools) | Named window by title, exact region | `cua_automation_visual(screenshot, window_handle=..., region=...)` | pywinauto, Pillow | Best — window-targeted, scriptable |
| **gdigrab** (FFmpeg) | Full screen or rectangle at offset | `ffmpeg -f gdigrab -offset_x 100 -offset_y 100 -video_size 1280x720 -i desktop` | FFmpeg (already core dep) | Good for full-demo captures, can't target by window title |
| **PIL fallback** | Full screen only | `PIL.ImageGrab.grab()` | Python stdlib (Pillow optional) | Last resort — no FFmpeg, no pywinauto |

gdigrab is the **default desktop fallback** — ships with FFmpeg which is already required for composition. Pipeline tries PyWinAuto first for window-targeted captures, falls back to gdigrab for region-at-offset, falls back to PIL.

Desktop capture flow:
1. PyWinAuto: find window by title → get window rect → capture region
2. gdigrab: validate offset+size → capture rectangle → crop
3. PIL: full-screen grab → no window isolation

For performance, desktop captures are single-shot (one frame per step) by default. A `record_duration_s` parameter on `capture_window` enables multi-frame sequences at 15 fps for animated demos (avatar spawning, Blender render completing, VRoid export progress).

### Human-in-video tier (OBS-mcp)

For repos where a real human presenter adds trust: OBS-mcp (10819) does scene compositing with a webcam PIP.

```yaml
steps:
  - action: obs_scene
    scene: "talking-head"
    wait: 3
    say: "Hi, I'm Sandra. Let me show you what this does."
  - action: obs_scene
    scene: "screen-only"
    wait: 5
    say: "Resonite MCP lets Claude control your worlds from a conversation."
```

Requires OBS Studio + obs-mcp running. Production tier — for the one polished video on README/YouTube, not weekly refresh.

### Install dependency chain (naked PC)

| Tier | Install command | What you get | Use case |
|------|----------------|--------------|----------|
| **Minimal** | `winget install FFmpeg` + `uv sync` | gdigrab screen record + speech-mcp TTS + compose | Webapp walkthrough |
| **Desktop** | + `pip install pywinauto Pillow` | Window-targeted capture, pre/post interactions | Host app demos (Resolve, Blender, Resonite) |
| **Production** | + OBS Studio from obsproject.com | Webcam PIP, scene switching, live presenter | One polished video |

All tiers are winget / pip — no manual compilation. `just bootstrap` installs Minimal by default.

### Naked PC testing via virtualization-mcp

Before release, test the install from scratch in a Windows sandbox VM (virtualization-mcp port 10700). This catches missing winget packages, PATH issues, and startup failures in a clean environment.

Test: create VM → `winget install FFmpeg && git clone repo && cd repo && just demo-vid generate repo` — from zero to video with zero manual steps.

### Fallback tiers

| Service missing | Fallback |
|----------------|----------|
| blender-mcp | gimp-mcp title card → plain text title |
| gimp-mcp | plain text title |
| davinci-resolve-mcp | FFmpeg composition |
| speech-mcp | No voiceover (silent video + subtitles only) |
| PyWinAuto (`cua_*`) | Fallback screenshot via `PIL.ImageGrab.grab()` |
| Desktop target window missing | Skip step, log warning, continue |

Only **speech-mcp** and **one capture mode** (either Playwright for webapp OR PyWinAuto for desktop) are required. The pipeline gracefully skips desktop steps when no PyWinAuto is available.

## Anti-patterns

- Recording empty dashboards (same content gate as screenshot standard)
- AI narration that sounds like marketing spam — factual, dry, useful
- No subtitles — many viewers watch on mute
- 3-minute video of sidebar navigation — show the product, not the furniture
- Trying to capture a desktop window that isn't installed (fail the step gracefully, don't crash the pipeline)
- Mixing webapp + desktop steps without context in the narration ("now watch the Blender viewport" without saying that's what you're showing)
