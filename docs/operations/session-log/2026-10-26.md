## git-github-mcp: gh search queries split into words (PR #7, branch fix/search-query-tokenize)
- Root cause: every `gh search` call passed the whole query as ONE argv word; gh
  quotes keywords containing spaces, so `user:x updated:>=D` became a phrase.
  search_issues errored ("Invalid search query"); search_repos, search_code,
  code_find_repos and search_repos_topic(owner=) silently returned unrelated
  repos; fleet_ops weekly retro swallowed the error and always reported 0.
- Fix: `utils/github_format.py` split_search_query + gh_search_args (flags, then
  `--`, then words). search_issues now honours owner=/repo=, new include_prs
  param (implied by is:pr), returns updatedAt + isPullRequest.
- Tests: 120 pass; 8 of 9 new search tests fail on old code. Live-checked.
- Overlaps PR #6 on the github_ops signature in server.py (adjacent lines).
- Running gitops MCP server still has the old code loaded until restarted.
