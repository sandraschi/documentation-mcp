## 2026-09-22 — opencode long sessions kill MCP servers - restart on recommence (Claude Code, human-driven session)

OPERATIONAL LEARNING (2026-09-22, from Sandra):
- MCP servers (fileops, gitops, memops) die when opencode is left running for days. Cause unknown (likely resource leaks or stale stdio handles in long-lived sessions), but the correlation is consistent.
- Failure mode is silent: tools vanish or crash, and work routed through them lands somewhere unexpected (e.g. memops notes written as raw zettelkasten files instead of via memops).
- PRACTICE ADOPTED: when recommencing work after days away, RESTART opencode (and verify MCP servers are back) before doing anything else. Do not trust a days-old session's tool list.
- For agents: if a memops/fileops/gitops call fails with tool-not-found or crash, stop and report it explicitly rather than improvising a workaround location. A note in the wrong place is worse than a note delayed by a restart.
