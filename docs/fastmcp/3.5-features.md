# FastMCP 3.5: Pluggable Storage, Caching, and OAuth Enhancements

**Last Updated:** 2026-07-20  
**Status:** Fleet target (`fastmcp>=3.5.0`)

3.5 is the **caching and storage** release: introducing pluggable persistent storage backends, response caching middleware to accelerate expensive tool executions, robust OAuth configurations (including Hugging Face, AzureB2C, PKCE flow), and SDK pinning to maintain path validation.

## 1. Pluggable Key-Value Storage

FastMCP 3.5 introduces native, pluggable persistent storage endpoints. This allows servers with persistent state (configurations, tokens, cache data) to swap backends without rewriting tool logic.

*   **Default Engine**: Memory-backed storage.
*   **Persistent Engine**: Integrates `py-key-value-aio` supporting SQLite, file-system storage, and key-value databases.
*   **MCP Integration**: Exposes key-value namespaces directly to tools via helper dependencies.

### Example: Storing context in a tool
```python
from fastmcp import FastMCP, Context

mcp = FastMCP("storage-demo")

@mcp.tool()
async def save_user_preference(key: str, value: str, ctx: Context) -> str:
    # Access the server-wide persistent key-value store
    await ctx.server.storage.set(f"pref:{key}", value)
    return f"Saved preference for {key}."
```

## 2. Response Caching Middleware

To improve performance for expensive operations (like running image analysis or querying large remote databases), FastMCP 3.5 introduces built-in **Response Caching**.

*   **Caching Strategy**: Automatic hashing of tool input parameters.
*   **Time-to-Live (TTL)**: Configurable on a per-tool basis.
*   **Skip-Cache**: Support for client-driven bypass headers.

### Example: Caching system diagnostics
```python
# Caches response for 60 seconds unless input params change
@mcp.tool(cache_ttl=60)
async def get_system_stats() -> dict:
    # Simulates a slow hardware query
    await asyncio.sleep(2)
    return {"status": "ok", "load": 1.2}
```

## 3. OAuth Enhancements & PKCE

OAuth integration has been updated to handle advanced security models:
*   **Hugging Face OAuth Provider**: Pre-configured provider featuring PKCE (Proof Key for Code Exchange) and Dynamic Client Registration (CIMD).
*   **AzureB2C Support**: Seamless integration for enterprise Azure directories.
*   **RFC 7662 Token Introspection**: Server-side token validation directly against the authorization server endpoints.

---

## 4. MCP SDK `< 1.17` Pinning

A critical maintenance update in 3.5 is the dependency constraint pinning `mcp<1.17.0`. 

### Why this pin was introduced:
*   **`.well-known` configuration path shifts**: MCP SDK 1.17 changed default lookup paths for host metadata.
*   **Auth Broker compatibility**: Pinning ensures that local reverse proxies and OAuth authentication broker services can resolve the OpenID metadata payload consistently.
*   **Tauri Desktop compatibility**: Prevents runtime socket failures when loading the server inside Tauri desktop shells.

## Fleet Recommendations for 3.5

1.  **Upgrade Server Pin**: Update your project `pyproject.toml` to require `"fastmcp>=3.5.0,<4"`.
2.  **Enable Caching for Stats/Status**: Any prefab status card tool (e.g. `podman_machine_status_card`) should declare a modest `cache_ttl` (10-30s) to prevent dashboard polling from spawning subprocess CLI calls concurrently.
