## The Paradigm Shift: Declarative Component Sourcing

FastMCP 3.x moved from **manual registration only** to **declarative component sourcing**.
Define **Providers** (sources) and **Transforms** (middleware) to assemble your server automatically.

Decorator-based registration (`@mcp.tool()`, etc.) still works — it is first-class alongside providers.

---

## Provider Architecture

Providers bring components into a server from an external source.

| Provider | Purpose |
|----------|---------|
| `FileSystemProvider` | Scripts/files in a directory → tools/resources, with hot-reload |
| `SkillsProvider` / `SkillsDirectoryProvider` | Anthropic-style skill dirs → MCP resources (`skill://`) — see [3.1-features.md](3.1-features.md) |
| `OpenAPIProvider` | MCP tools from Swagger/OpenAPI (large catalogs from a spec) |
| `ProxyProvider` | Mirror another MCP server — federation without re-registering every tool |

```python
from fastmcp import FastMCP
from fastmcp.server.providers import FileSystemProvider, ProxyProvider

mcp = FastMCP(
    "Central Hub",
    providers=[
        FileSystemProvider(root="./my_tools", name="local"),
        ProxyProvider(url="http://localhost:8000/sse", name="camera-server"),
    ],
)
```

`ProxyProvider` is the main primitive for **federation**: one FastMCP server can expose another server’s tools transparently.

---

## Transforms (Middleware)

Transforms modify or filter components after they are sourced.

| Transform | Purpose |
|-----------|---------|
| `NamespaceTransform` | Prefix components: `list_files` → `fs_list_files` |
| `RenameTransform` | Custom name mapping |
| `ArgTransform` | Rename or hide tool arguments |
| `VisibilityTransform` | Filter by version tags / feature flags |
| `CodeMode` (3.1) | Meta-tool pattern for large catalogs — see [code-mode.md](code-mode.md) |

```python
from fastmcp.server.transforms import NamespaceTransform

mcp = FastMCP("Hub", providers=[...])
mcp.add_transform(NamespaceTransform(prefix="local"))
```

## Breaking Changes from 2.x (still the baseline in 3.1)

These landed in the 3.x line. If you are already on 3.1, you have already absorbed them.

| Change | Impact | Fix |
|--------|--------|-----|
| `@mcp.tool()` returns the original function, not a component object | Low | Only if you relied on the decorator return as `FunctionTool` |
| `ctx.set_state()` / `ctx.get_state()` are **async** | Medium | Use `await` |
| 16 deprecated `FastMCP()` constructor kwargs removed | Low | Drop stale kwargs |
| `mount(subserver, prefix=...)` → `mount(subserver, namespace=...)` | Low | Rename kwarg |
| `mcp.add_tool_transformation()` → `mcp.add_transform()` | Low | Rename if used |
| `FastMCP.as_proxy()` → `create_proxy()` | Low | Update proxy servers |
| `ctx.session.create_message()` removed | Medium | Use **`ctx.sample()`** (see [sep-1577-sampling-with-tools.md](sep-1577-sampling-with-tools.md)) |

## Startup (3.1)

Prefer the unified entrypoint; use stdio-async when your layout requires it. Do **not** use `run_standalone()`.

```python
# ✅ Recommended (stdio / default transport)
if __name__ == "__main__":
    mcp.run()
```

```python
# ✅ Explicit async stdio
if __name__ == "__main__":
    import asyncio
    asyncio.run(mcp.run_stdio_async())
```

Dual HTTP + stdio in one process: use **`run_server()`** (see [migration-guide.md](migration-guide.md)).

## CLI (`fastmcp`)

```powershell
# Discover MCP servers from Claude Desktop / Cursor config
fastmcp discover --client claude

# List tools from a server module (no desktop required)
fastmcp list "D:\Dev\repos\my-server\src\my_package\server.py"

# Call a tool directly
fastmcp call "D:\Dev\repos\my-server\src\my_package\server.py" my_tool --arg value
```
