# FastMCP 3.1 Features: Prompts and Skills

**Last Updated:** 2026-03-17
**Status:** Active
**Applies to:** FastMCP 3.1+

FastMCP 3.1 adds **Prompts** (reusable, parameterized message templates), **Skills Provider** (expose agent skills as MCP resources), and **CodeMode** (the headline 3.1 feature — agentic tool discovery + sandbox execution). Both prompts and skills help clients guide LLM behavior without hard-coding instructions in the client. CodeMode solves catalog bloat and sequential round-trips for large servers.

**Fleet-wide “when to use what” (prompts vs skills vs Prefab vs CodeMode vs sampling):** [fastmcp-31-fleet-capability-map.md](fastmcp-31-fleet-capability-map.md).

## Prompts (`@mcp.prompt`)

Prompts are reusable message templates. When a client requests a prompt with arguments, the server runs the prompt function and returns one or more messages that the client can inject into the conversation (e.g. as system or user context).

### Why use prompts

- **Consistent guidance**: One prompt can encode "act as a database expert and use these tools in this order" so any MCP client (Cursor, Claude Desktop, custom) gets the same instructions.
- **Parameterization**: Optional arguments (e.g. `focus: "sql"` vs `"connections"`) tailor the returned text without maintaining separate docs per client.
- **Discoverable**: Clients that support MCP can list prompts and let the user or LLM choose one.

### Definition

```python
from fastmcp import FastMCP

mcp = FastMCP("MyServer")

@mcp.prompt(
    name="database_expert",
    description="Load instructions for acting as a database expert using this server's tools.",
    tags={"database", "expert"},
)
def database_expert(focus: str = "general") -> str:
    """Return system-style instructions for database expert behavior."""
    base = "You are a database expert. Use db_connection for connections, db_schema for schema..."
    if focus == "sql":
        return base + "\n\nPrefer safe SELECTs and parameterized queries."
    return base
```

### Client usage

Clients call `get_prompt(name, arguments={...})` and receive the rendered message(s), then inject them into the conversation so the model follows the guidance. See [FastMCP Prompts](https://gofastmcp.com/servers/prompts) for full API (return types: `str`, `list[Message]`, `PromptResult`).

## Skills Provider

The **Skills Provider** exposes skill directories (e.g. folders containing `SKILL.md`) as MCP **resources** under the `skill://` URI scheme. Clients that support MCP resources can list and read these files to load expert instructions or reference material.

### Why use skills

- **Portable**: Skills are directories with a main file (default `SKILL.md`) and optional supporting files. Same format used by Claude, Cursor, and other tools for user-installed skills.
- **Shareable**: An MCP server can bundle skills and expose them so any client can read `skill://my-skill/SKILL.md` without the user copying files.
- **Manifest**: Each skill exposes a `_manifest` resource (file list, sizes, hashes) so clients can discover supporting files.

### Skill structure

```
skills/
└── database-expert/
    └── SKILL.md    # Main instructions (YAML frontmatter optional)
```

### Registering the provider

```python
from pathlib import Path
from fastmcp import FastMCP
from fastmcp.server.providers.skills import SkillsDirectoryProvider

mcp = FastMCP("MyServer")
skills_dir = Path(__file__).resolve().parent / "skills"
if skills_dir.is_dir():
    mcp.add_provider(SkillsDirectoryProvider(roots=[skills_dir]))
```

Clients then see resources such as `skill://database-expert/SKILL.md` and `skill://database-expert/_manifest`, and can read their contents.

### Vendor providers

FastMCP includes pre-configured providers for platform skill directories: `ClaudeSkillsProvider` (~/.claude/skills/), `CursorSkillsProvider` (~/.cursor/skills/), etc. Use these when you want to expose the user's existing skills; use `SkillsDirectoryProvider(roots=[...])` when you want to expose **bundled** skills from your package.

See [Skills Provider](https://gofastmcp.com/servers/providers/skills) for full docs. **Who runs it?** The skill provider is **your server**—not Anthropic. There is no single “big repository” in FastMCP; see [SKILLS_OVERVIEW.md](SKILLS_OVERVIEW.md) for clarification.

## CodeMode (Experimental) — The 3.1 Headline Feature

CodeMode is the most significant addition in 3.1. It solves two problems: context bloat (full tool catalog dumps into context at session start) and sequential round-trips (each tool call flows through context individually).

**How:** Replaces the tool catalog with meta-tools. The LLM searches (BM25), inspects schemas, then writes Python that executes tool calls in a sandbox. Intermediate results stay in the sandbox.

```python
from fastmcp import FastMCP
from fastmcp.experimental.transforms.code_mode import CodeMode

mcp = FastMCP("Server", transforms=[CodeMode()])
# Your existing tools don't change
```

**Install:** `pip install "fastmcp[code-mode]"`

**Default flow:** search → get schemas → execute (3 stages, configurable)

**Relevance for our fleet:** Our portmanteau pattern already solves catalog bloat differently. CodeMode is most useful for servers with diverse unrelated tools, wrapping third-party servers via proxy, or OpenAPIProvider-generated tool sets.

Full documentation: **`fastmcp/code-mode.md`**
Full improvements: **`fastmcp/3.0-to-3.1-improvements.md`**

## Example: database-operations-mcp

The **database-operations-mcp** server uses both:

- **Prompt**: `database_expert` with optional `focus` (general, sql, connections, export). Clients get prompt text to inject so the LLM acts as a database expert and uses db_connection, db_schema, db_operations, etc. correctly.
- **Skill**: Bundled `database-expert` skill in `src/database_operations_mcp/skills/database-expert/SKILL.md`, exposed via `SkillsDirectoryProvider`. Clients can read `skill://database-expert/SKILL.md` for the same guidance.

See [Integrations: Database Operations](../integrations/database-operations/README.md) for that server's details.
