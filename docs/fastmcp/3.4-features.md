# FastMCP 3.4: Remote Control, Proxy Hardening & Returnable Errors

**Last Updated:** 2026-06-06  
**Status:** Fleet target (`fastmcp>=3.4.4`)  
**Applies to:** FastMCP 3.4.0+ (released June 2026)

3.4 is the **remote connectivity** release: stdio hosts can reach HTTP MCP servers via `fastmcp-remote`, proxies fail loudly on misconfiguration, OAuth sessions survive idle time, and tools can return structured errors without raising.

For the prior GA baseline see [3.2-features.md](3.2-features.md). For bridge fleet patterns see [mcp-bridge-fleet-patterns.md](mcp-bridge-fleet-patterns.md).

## 1. `fastmcp-remote` — stdio bridge to HTTP servers

Some MCP hosts (Cursor, Claude Desktop) only launch **local stdio** commands even when the server you want already runs over HTTP. FastMCP could proxy via `fastmcp run`, but that pulls in the full server-runner surface.

**`fastmcp-remote`** is a single-purpose package: one URL in, one local stdio proxy out. OAuth is enabled automatically for HTTPS endpoints.

### Cursor / Claude Desktop config

```json
{
  "mcpServers": {
    "linear": {
      "command": "uvx",
      "args": ["fastmcp-remote", "https://mcp.linear.app/mcp"]
    }
  }
}
```

### When to use in the fleet

| Scenario | Pattern |
|----------|---------|
| Server already on HTTP (10700–10800 range) but host is stdio-only | `uvx fastmcp-remote http://127.0.0.1:10718/mcp` |
| External SaaS MCP (HTTPS + OAuth) | `uvx fastmcp-remote https://…/mcp` |
| Local dev, full runner acceptable | Keep `create_proxy()` inside the server or `fastmcp run` |

Credits the npm `mcp-remote` command shape; implementation uses FastMCP `Client`, OAuth, `create_proxy`, and stdio.

## 2. Proxy “fail loudly” (breaking vs 3.3)

As of 3.4, **`initialize` and `ping` are forwarded upstream**. A proxy only reports a successful handshake after the upstream server initializes.

### What now fails at connect time (instead of empty tool lists)

- Missing or stopped backend
- Wrong URL (server root instead of `/mcp`)
- Denied upstream auth
- Non-MCP upstream

### Fleet impact

Servers using `create_proxy()` or `MCP_BRIDGE_URLS` (meta-mcp, docker-mcp, observability-mcp, federation hubs) **benefit** from clearer startup failures.

**Do not swallow proxy registration errors.** Prefer logging or failing startup:

```python
# ❌ Anti-pattern — hides 3.4 fail-loud behavior
try:
    app.add_provider(create_proxy(url))
except Exception:
    pass

# ✅ Log or raise so misconfigured MCP_BRIDGE_URLS is visible
try:
    app.add_provider(create_proxy(url))
    logger.info("Bridge registered: %s", url)
except Exception as exc:
    logger.error("Bridge failed for %s: %s", url, exc)
    raise
```

Full bridge patterns: [mcp-bridge-fleet-patterns.md](mcp-bridge-fleet-patterns.md).

## 3. OAuth: sessions that survive idle time

Remote clients sit idle; short upstream `expires_in` values (e.g. 5 minutes) used to force full re-auth.

### `fastmcp_access_token_expiry_seconds`

Decouples the **FastMCP-issued** token lifetime from upstream `expires_in`. The FastMCP token is a reference into proxy storage, re-validated and refreshed on each request.

```python
from fastmcp.server.auth.providers.github import GitHubProvider

auth = GitHubProvider(
    client_id="...",
    client_secret="...",
    base_url="https://your-server.example",
    fastmcp_access_token_expiry_seconds=60 * 60 * 24,  # 24h client-facing token
)
```

When the upstream issues no refresh token, lifetime is capped to match upstream policy.

### `token_expiry_threshold_seconds`

Treat tokens as expired **N seconds early** to close refresh races (3.4.0). Use on any OAuth-proxied HTTP server with long-lived sessions.

### 3.4.1 / 3.4.2 auth fixes

- **3.4.1:** OAuthProxy logs refresh-token cache misses instead of failing silently.
- **3.4.2:** JWT validation accepts private, non-critical JWS header parameters (Clerk and similar providers).

## 4. `ToolResult(..., is_error=True)`

Previously, tools could only signal failure by **raising**, which flattens to text and drops structured content. In 3.4, `ToolResult` accepts `is_error=True`, mapping to MCP `CallToolResult.isError`.

### Prefab error cards (fleet pattern)

Return rich UI **and** mark the call as an error for the model:

```python
from fastmcp.tools import ToolResult
from prefab_ui import PrefabApp, Card, CardHeader, CardTitle, CardContent, Text

@mcp.tool(app=True)
async def show_status_prefab() -> ToolResult:
    ok, summary = await probe_backend()
    if not ok:
        with Card(css_class="max-w-md") as view:
            with CardHeader():
                CardTitle("Unavailable")
            with CardContent():
                Text(summary)
        return ToolResult(
            content=summary,
            structured_content=PrefabApp(view=view, title="Error"),
            is_error=True,
        )
    # success path ...
```

Proxies forward upstream tool errors with `is_error` intact instead of collapsing them.

See also [generative-ui-prefabs.md](generative-ui-prefabs.md) and [TOOL_DESIGN_STANDARDS.md](../standards/TOOL_DESIGN_STANDARDS.md) §3.3.

|-------|---------|---------|
| Duration | 30s | `limits=None` |
| Memory | 100 MB | `limits=None` |

Servers with CodeMode (blender-mcp, large portmanteau catalogs) should verify they do not rely on unlimited sandbox execution. Details: [codemode-discovery.md](codemode-discovery.md).

### ASGI Lifespan Pitfall (Critical for FastMCP 3.4.4+)

When `mcp.http_app()` is called, it returns a `StarletteWithLifespan` — a Starlette app whose lifespan wraps both the original FastMCP `@mcp.lifespan()` and the **StreamableHTTPSessionManager** lifecycle. **This lifespan must be passed to the parent ASGI app**, or POST to `/mcp/` crashes with 500:

```
RuntimeError: FastMCP's StreamableHTTPSessionManager task group was not initialized.
Please ensure you are setting `lifespan=mcp_app.lifespan` in your parent app's constructor.
```

#### Fix: pass `lifespan=mcp_http_app.lifespan`

```python
# BEFORE (3.4.3) — crashes on POST /mcp/:
web_app = FastAPI(title="My Server")
web_app.mount("/mcp", mcp.http_app(path="/"))

# AFTER (3.4.4+) — works:
_mcp_http = mcp.http_app(path="/")
web_app = FastAPI(title="My Server", lifespan=_mcp_http.lifespan)
web_app.mount("/mcp", _mcp_http)
```

#### Merging with existing FastAPI lifespan

If the FastAPI already has a lifespan, move its logic to `on_event` handlers:

```python
_mcp_http = mcp.http_app(transport="streamable-http", path="/")
app = FastAPI(title="My Server", lifespan=_mcp_http.lifespan)

@app.on_event("startup")
async def my_startup():
    check_auth()
    start_background_tasks()

@app.on_event("shutdown")
async def my_shutdown():
    stop_background_tasks()
```

#### Do not run stdio + HTTP on the same mcp instance

A single `FastMCP()` manages one lifespan context. Running both `mcp.run_stdio_async()` and the HTTP transport triggers duplicate lifespan:

```python
# WRONG — lifespan conflict
http_thread = Thread(target=lambda: uvicorn.run(web_app))
http_thread.start()
asyncio.run(mcp.run_stdio_async())  # second lifespan invocation
```

Use `fastmcp-remote` for stdio-only clients connecting to the HTTP server:

```json
{"mcpServers": {"my-server": {"command": "uvx",
  "args": ["fastmcp-remote", "http://127.0.0.1:10702/mcp"]}}}
```

#### Also requires `Accept` header

FastMCP 3.4.4 streamable HTTP rejects clients that do not accept both `application/json` and `text/event-stream` (406 Not Acceptable). Probe correctly:

```bash
curl -sL -X POST "http://localhost:PORT/mcp/" \
  -H "Accept: application/json, text/event-stream" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize",...}'
```

## 8. Upgrade checklist (2.x / 3.2 → 3.4.2)

1. **`pyproject.toml`:** `fastmcp>=3.4.4,<4`
2. **`uv sync`** (or fleet SOTA Bash equivalent)
3. **Proxy servers:** remove silent `except: pass` on `create_proxy()`; expect handshake failures on bad URLs
4. **Prefab tools:** adopt `is_error=True` on failure paths that still return UI
5. **CodeMode servers:** confirm sandbox defaults are acceptable
6. **HTTP/OAuth servers:** bump for Starlette CVE floor (3.4.1+)
7. **Clerk / custom JWT headers:** bump to 3.4.2
8. **Optional:** document `fastmcp-remote` in server README for stdio-only clients
