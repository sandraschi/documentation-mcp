## 4. Background Tasks (SEP-1686)

Tools can run persistently without blocking the MCP connection by setting `task=True`:

```python
@mcp.tool(task=True)
async def slow_operation(ctx: Context) -> str:
    await asyncio.sleep(60)
    return "Done!"
```

Returns a Task ID immediately; client stays responsive. Full protocol: [sep-1686-background-tasks.md](./sep-1686-background-tasks.md)

## 1. Tool Concurrency (Task Protocol)

FastMCP 3.2 fully implements **SEP-1686: The Background Task Protocol**. This allows tools to run persistently without blocking the primary MCP connection.

### How it works
By setting `task=True` in the `@mcp.tool` decorator, the tool call immediately returns a **Task ID** to the client. The server then executes the tool in the background.

```python
@mcp.tool(task=True)
async def slow_operation(ctx: Context) -> str:
    # This runs in the background
    await asyncio.sleep(60)
    return "Done!"
```

### Key Benefits
- **Non-blocking**: The client remains responsive while the server works.
- **Persistent Monitoring**: Ideal for filesystem watchers, long-running deployments, or data migrations.
- **Cancellation Support**: (Upcoming) Clients will be able to cancel tasks via Task ID.

## 2. Agentic Sampling (`ctx.sample`)

FastMCP 3.2 enhances sampling to support **Autonomous Tool Selection** (Federated AI).

### The Pattern
A server can "sample" the model to decide which tool to call next, potentially across different MCP servers in the same fleet.

```python
@mcp.tool()
async def analyze_and_repair(ctx: Context):
    # Ask the LLM to analyze the current state using ANY available tool
    result = await ctx.sample(
        messages=[{"role": "user", "content": "Analyze system health and repair issues."}],
        tools=["check_disk", "disk_cleanup", "fileops.reindex"]
    )
    return result
```

## 3. Universal Providers

FastMCP 3.2 introduces the **Provider** abstraction for LLM fallback. If the connected client (Claude Desktop) does not support sampling, the server can use its own LLM backend.

### Configuration
```python
from fastmcp.providers import AnthropicProvider

mcp = FastMCP(
    "MyServer",
    providers=[AnthropicProvider(api_key="...")]
)
```

## 4. Lifecycle Improvements

The `@mcp.on_startup` and `@mcp.on_shutdown` hooks now support **Full Lifespan management**, allowing for clean initialization of background observers (like `watchdog`) and telemetry connections.
