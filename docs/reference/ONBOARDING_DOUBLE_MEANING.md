# Onboarding, both senses

**Status:** Reference v1 2026-10-05 - the joke with a real payload. Companion to [standards/ONBOARDING_STANDARD.md](../standards/ONBOARDING_STANDARD.md) (fleet sense) and [reference/YC_GARAGE_TO_BATCH.md](./YC_GARAGE_TO_BATCH.md) (founder sense).
**Tags:** [fleet, reference, onboarding, y-combinator]

## Sense 1 (fleet): the bridge is useless until the world is connected

Per the standard: INSTALL.md gets the MCP process running, but onboarding answers what world you are joining and what must be true before any tool call brings joy. Wrappee installed (Blender, Unity, a Nori robot), account created, token pasted, health probe green. Until then: big red under-hero CTA and MOCK-until-onboarded sample data with visible MOCK badges, because fake-real numbers are worse than openly fake ones.

## Sense 2 (founder): the startup is useless until reality is connected

Same shape, bigger stakes. Incorporation is the account creation. The bank account is the API token. The flip to a Delaware parent is the OAuth dance nobody enjoys but everybody must complete. Weekly partner meetings are the health probe. And the pitch deck's hockey-stick projection is MOCK-until-onboarded revenue - openly sample data until traction replaces it, at which point the badges come off.

## The mapping (played straight)

| Fleet onboarding | Founder onboarding |
|---|---|
| Wrappee / host app must be installed | Product must exist as a demo a stranger can touch |
| Account + API token | Incorporation + bank account + cap table |
| Money/CC table (who bills, free tier?) | Burn plan (who pays, how many months?) |
| docs/ONBOARDING.md first-timer narrative | YC application + 1-minute video |
| Big red under-hero CTA | Demo Day |
| Health probe flips "configured" | Weekly growth check flips "fundable" |
| MOCK badges until real data flows | Projections labeled as projections until revenue flows |
| Exempt only if no wrappee and no account | Exempt only if bootstrapped and profitable (congratulations) |

## Why the joke earns its keep

Both onboardings answer one question: **is this thing actually connected to reality yet?** The fleet learned to distrust unbadged mock KPIs; investors learned to distrust unbadged mock traction. The standard's answer in both worlds is identical: mark the sample data, name the missing connection, show the button that completes it.

The crosser of both worlds is the Nori shape: a YC-backed robotics startup (sense 2, done) whose SDK ends up wrapped as a fleet MCP with its own docs/ONBOARDING.md (sense 1, pending). One company, two red buttons. And the essay about all of it ships on the Astro site whose own onboarding is mercifully just "open the URL."
