# RAG add-on for Tauri desktop apps (lazy download)

**Status: proposed (requirement confirmed 2026-10-07, not yet implemented).** Reference
implementation to be built in `email-mcp`, then rolled out repo by repo.

## 1. Problem

The fleet RAG stack (`ai-rag-2026.md`: LanceDB + FastEmbed bge-small) cannot ship inside a
PyInstaller sidecar:

- **Size.** `lancedb` + `fastembed` + `onnxruntime` + `pyarrow` + `numpy` are hundreds of MB
  (estimate, not measured), plus a ~130 MB embedding model downloaded on first use.
- **Frozen-import fragility.** `onnxruntime` and `numpy` can clash with the copies PyInstaller
  already froze, and the DLL search paths need special handling.
- **Wrong data path.** Code written for dev resolves "repo root" from `__file__`; in a onefile
  exe that is a temp `_MEI*` folder, so the index would vanish on every launch.
- **Policy already says so.** `LLM_AND_INSTALL_TIERS.md`: never bundle models in MCPB/Tauri.

Observed in `email-mcp` 0.6.0: the RAG tools import `lancedb` at module load, so an unguarded
registration stops the server from starting wherever the dependency is absent (installer,
mcpb). Guarded registration (`_register_optional_rag`) is the required floor; this standard is
the ceiling: make RAG *available* on desktop without bundling it.

## 2. Standard

An **opt-in RAG add-on**, downloaded on demand, run as a **separate process**.

1. **Opt-in, with consent.** The app shows "Enable semantic search" with the real download size
   and a privacy note. Nothing is downloaded before the user clicks.
2. **Private environment** under `%LOCALAPPDATA%\{identifier}\rag-env`, created by `uv`
   (managed Python 3.12) and populated from a **pinned, hashed** requirements file
   (`uv pip install --require-hashes`). `uv` itself is fetched over HTTPS from its official
   release with a pinned version and verified SHA-256. Never "latest".
3. **Worker process.** A small pure-Python worker (shipped as a Tauri resource, light deps only)
   runs in that environment and speaks JSON lines over stdio. No extra port, so nothing to
   claim or collide. The frozen backend never imports `lancedb`/`fastembed`.
4. **Backend contract.** `rag_status()` returns `{state: not_installed | installing | ready |
   error, progress, detail}`. RAG tools called while not ready return a structured result with
   `success: false`, `state`, and a human-readable action hint; they never raise.
5. **Data location.** Index, model cache and worker logs live under
   `%LOCALAPPDATA%\{identifier}\rag\`. Never `_MEIPASS`, never the install dir. Uninstall of the
   add-on is deleting that folder; the NSIS uninstaller offers it.
6. **Failure is contained.** Offline, partial download, antivirus quarantine or a failed install
   leave the rest of the app fully working and the add-on retryable.
7. **Privacy.** The index holds the indexed text unencrypted on disk; the UI says so and the
   worker must never index secrets (token files, `.env`).

## 3. Shared component (one implementation, many repos)

Lives in `templates/rag-addon/` (to be created); repos copy and wire it, they do not fork it:

| Piece | Role |
|---|---|
| `worker/` | stdio JSON-lines worker: ingest, search, stats, health |
| `bootstrap.rs` (+ Tauri commands) | download uv, create env, install pinned deps, progress events |
| `RagAddon.tsx` | status card, enable button, progress, error + retry |
| `rag-addon.lock` | hashed pins, regenerated by one script |
| tests | fake-worker contract tests; smoke phase for the CUA run |

## 4. Acceptance (per repo)

CUA smoke additions: fresh install shows RAG `not_installed` and every RAG tool answers
cleanly; enabling installs and reaches `ready`; sync + search return results; offline retry
works after a forced failure; removing the add-on restores `not_installed` without touching
the rest of the app.

## 5. Candidates (inventory 2026-10-07)

Repos with a Tauri `native/` app **and** `lancedb`/`fastembed`/`onnxruntime` in their declared
`pyproject.toml`/`requirements.txt` (19 of 170 native repos). Declared dependency only: whether
each installer currently bundles it, breaks on it, or has it as an optional extra must be
checked per repo before adoption.

`arxiv-mcp`, `calibre-mcp`, `database-operations-mcp`, `depot-mcp`, `discord-mcp`,
`documentation-mcp`, `email-mcp`, `jellyfin-mcp`, `mcp-central-docs`, `notion-mcp`,
`obsidian-mcp`, `opencode-cli-mcp`, `plex-mcp`, `resonite-mcp`, `robofang`, `speech-mcp`
(also onnxruntime), `teleconference-mcp`, `tvtropes-mcp`, `universal-actuator-mcp`.

Rollout rules: reference implementation in `email-mcp` first; then one repo per change set
(Batch Size Limit, Batch Mutation Safety), each with its own installer smoke run. No fleet
sweep.

## 6. Open decisions

- Per-repo vs shared model cache (disk vs isolation).
- GPU variant (`fastembed-gpu` / `onnxruntime-gpu`): offer as a second, explicit download.
- Whether the add-on may also serve non-Tauri installs (MCPB) through the same worker.
