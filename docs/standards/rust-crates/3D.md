# 3D Viewing in Pure Rust (Three.js Replacement)

For rendering 3D content — AI-generated models (Hunyuan3D GLBs in Pinokio),
fleet "model preview" needs (PCB GLB), digital-twin viewports — with
**dynamic viewing** (orbit / zoom / pan).

## The pick: `three-d` 0.19 (verified 2026-10-17, MIT)

Three.js's philosophical twin: explicit scene/camera/mesh/material/light
API, "draw something in a few lines", desktop + web + mobile.

- **Dynamic viewing**: `OrbitControl` built in (orbit + wheel zoom + pan).
- **glTF/GLB**: `three-d-gltf-import` 0.0.3 + `three-d-asset` (same version).
- **WASM/WebGL2** builds documented.
- **egui integration**: `egui` + `egui-gui` cargo features, and `eframe`
  is a documented window replacement — a 3D viewport tab inside our egui
  dashboards is a supported path, not a hack.
- Text: `three-d-text-builder` 0.7.0 (glyph-atlas labels).

Caveats: OpenGL 3.3 backend (not wgpu — fine on Windows/Linux, weak corner
on macOS where Apple deprecated GL); pre-1.0 API churn; single maintainer
(asny). Pin exact versions.

## Alternatives (narrower doors)

| Crate (version) | Use when |
|---|---|
| `rend3` 0.3 (+ `rend3-routine`) | Custom wgpu-native pipeline required (matches our egui/wgpu backend); costs ~10× the code of `three-d` for the same viewport |
| `kiss3d` 0.47 | Five-minute prototype only — maintenance mode, nalgebra-era API |
| `bevy` 0.20 | Full engine justified (see BEVY.md) — never for "just a viewer" |

## Fleet rule

`three-d` for viewer/clone jobs (GLB preview tabs, twin viewports, parity
captures of 3D scenes). Anything bigger needs the Bevy justification note.
First customer candidate: a GLB viewer pointed at the Hunyuan3D weights.
