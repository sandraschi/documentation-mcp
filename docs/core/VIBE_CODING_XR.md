# SOTA Standard: Vibe Coding XR (v1.0.0)

## 1. Overview
**Vibe Coding XR** is an industrialized rapid-prototyping workflow that leverages high-reasoning LLMs (Gemini 3.1 Pro) and specialized physics-aware SDKs (XR Blocks) to transform natural language "vibes" into functional WebXR experiences in under 60 seconds.

## 2. Technical Substrate

### 2.1. The reasoning Engine (Gemini 3.1 Pro)
- **Model Requirement**: MANDATORY use of **Gemini 3.1 Pro** for production-grade interaction logic (95% error-free rate).
- **Reasoning Budget**: Use "Thinking" or "Pro" modes to handle spatial coordinate logic and physics colliders.
- **Canvas Integration**: Standard SOTA development occurs in the Gemini Canvas for real-time iterative refinement.

### 2.2. The SDK (XR Blocks)
- **Physics awareness**: Native collider inference from text descriptions.
- **Input Bandwidth**: Built-in support for hand tracking (pinch, grab, proximity).
- **Simulator**: Automated mapping of mouse/WASD to virtual XR hands for non-headset testing.

## 3. Industrial Workflow (EPI-C Loop)

1.  **Extract (Prompting)**: Provide high-density intent (e.g., "Midcentury Villa interior with gravity-defying physics triggers").
2.  **Produce (Vibing)**: Generate HTML/JS/CSS in the Gemini Canvas side-panel.
3.  **Inspect (Simulator)**: Validate basic physics and UI layout on PC using the XR Blocks simulator.
4.  **Confirm (Headset)**: "Launch-to-Device" via WebXR browser (Quest 3, Vision Pro) for first-person validation.

## 4. Integration with Antigravity Fleet

- **Interaction Mocks**: Use Vibe Coding XR to validate UX before final baking into Resonite or custom Unity/WebXR frameworks.
- **Narrative Grounding**: Generated interaction triggers should be linked to the [[speech-mcp]] agent for spatialized audio feedback.
