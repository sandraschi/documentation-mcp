# The back-office craft suite

Nine pure-Rust craft apps that together replace the SaaS back office of a small
Austrian business: bookkeeping, tasks, HR time records, assets, contracts,
support, customer success, surveys and an engineering knowledge base. Each is a
normal fleet craft app (L1 core + store, L2 CLI/MCP binary, L3 egui app), so a
human can click it and an agent can drive it through the same command bus.
The point of the suite is to stop renting that work. Peppol is one of those rents:
the network is open, the access-point seat is the product being cut. See `PEPPOL.md`.

This doc does three things:

1. Says what the suite is and why it is worth building (section 1).
2. Corrects the Gemini drafts against fleet standards (section 2). The drafts
   are good domain research and poor implementation specs.
3. Gives the build plan, per-app command surface and phasing (sections 3-6).

**Progress (2026-11-09):** Phase 0 done: `craft-biz` (31 tests: money,
AT validators, EKR, deadlines, holidays, bus, MCP loop, confinement).
buchcraft: Tier 1 + egui app v0.2.0, 22 MCP tools, 27 tests, see
`projects/craft-fleet/buchcraft.md`.
taskcraft: Tier 1 + L3 egui app v0.1.3, 17 MCP tools, 20 tests (git sync tested
against a real repo), full egui workstation, see `projects/craft-fleet/taskcraft.md`.
teamcraft: Tier 1 v0.1.0, 25 MCP tools, 22 tests, AZG engine, no GUI yet,
see `projects/craft-fleet/teamcraft.md`.
assetcraft: Tier 1 v0.1.0, 24 MCP tools, 21 tests, AfA engine, no GUI yet,
see `projects/craft-fleet/assetcraft.md`.
contractcraft: Tier 1 v0.1.0, 17 MCP tools, 22 tests, risk rules + Ed25519
seal, no GUI yet, see `projects/craft-fleet/contractcraft.md`.
deskcraft: Tier 1 v0.1.0, 14 MCP tools, 20 tests, eml/maildir ingest with
threading, business-hours SLA, no GUI yet, see `projects/craft-fleet/deskcraft.md`.
gaincraft: Tier 1 v0.1.0, 16 MCP tools, 22 tests, aggregate-only telemetry,
explainable health score + CTAs, no GUI yet, see `projects/craft-fleet/gaincraft.md`.
Bus links live (verified end to end with real binaries):
teamcraft `capacity.changed` -> taskcraft; assetcraft `asset.depreciation_due`
-> buchcraft draft -> approved -> booked; contractcraft `contract.deadline`
-> taskcraft issue; deskcraft `ticket.escalated` -> taskcraft issue;
contractcraft `contract.executed` -> gaincraft ARR + notice date;
deskcraft `signal.negative` -> gaincraft sentiment.
Docs standard for every suite repo (2026-11-09): README, HELP.md, docs/PRD.md,
docs/TOOLS.md generated by `<app> tools --markdown` and checked by a test
(`just docs` regenerates), CHANGELOG, AGENTS.md "Docs" section.
Next: formcraft. All repos are local commits on `main`, not pushed.

## 1. What it is, and is it radical?

| App | Replaces | Core idea |
|---|---|---|
| **buchcraft** | BMD, RZL, sevDesk, DATEV | Austrian EKR double-entry ledger, Storno-only corrections, George CSV import, U30 pre-fill |
| **taskcraft** | Jira, Linear | Local issue tracker bound to git refs |
| **teamcraft** | Personio, BambooHR (time + leave only) | AZG-checked time records, leave balances, KV wage-floor check |
| **assetcraft** | Snipe-IT, Lansweeper | Hardware/licence inventory with AfA/GWG schedule in integer cents |
| **contractcraft** | Ironclad, PandaDoc (not DocuSign) | Templates, clause risk rules, redlines, deadlines, integrity seal |
| **deskcraft** | Zendesk, Freshdesk | Mail-to-ticket with real threading, SLAs, macros, escalation |
| **gaincraft** | Gainsight, Planhat | Deterministic health score, cancellation-deadline CTAs |
| **formcraft** | Typeform, Qualtrics | Forms, responses, NPS, local sentiment |
| **wikicraft** (was "doccraft", see 7.1) | Confluence, Notion | Markdown + ADR knowledge base with hybrid search |

**Radical in scope and posture, conventional in technology.** The stack is
SQLite plus a native binary, which is how BMD and RZL shipped in the 1990s. What
is new:

- **The clerk is an agent.** Every app is designed so an MCP client can do the
  routine work (classify a bank line, triage a ticket, flag an AZG breach) while
  the human approves. Commercial tools bolt an API onto a web UI; here the
  command bus is the product and the GUI is one client of it.
- **Austrian law is in the engine, not in a consultant's config.** Kuendigungsfrist
  instead of renewal date, ArbVG-safe aggregate telemetry, AZG rest periods,
  EKR classes, U30 Kennzahlen, GWG limit, KESt.
- **Zero per-seat cost and zero data egress.** Nine SaaS subscriptions for a
  10-person firm run roughly 1,500-4,000 EUR a month.

**Where it is not radical, and where it is risky:**

- Breadth. Nine apps at grade B- are worth less than three at grade A. The plan
  below builds the ledger first and makes everything else feed it.
- No real user yet. The oracle loop (`standards/rust-artcraft/ORACLE_LOOP.md`)
  needs real data. Without a business producing invoices, tickets and
  timesheets, most of this gets validated against synthetic fixtures only. A
  pilot user (a small Viennese firm, a Verein, or Sandra's own bookkeeping)
  should be named before Phase 2.
- Legal weight. buchcraft does not file with FinanzOnline and is not a
  certified Registrierkasse; contractcraft seals are not qualified electronic
  signatures; teamcraft is not payroll. These are explicit non-goals (section 5).

## 2. What was wrong in the Gemini drafts

Read for the domain research, rewrite the code.

### 2.1 Violations of fleet standards

| Gemini draft | Fleet standard | Fix |
|---|---|---|
| `rmcp` with an invented API (different in every doc), versions `0.1.0` and `0.16` | Hand-rolled MCP `2024-11-05` stdio loop, `tools_list()` and `call_tool()` as pure functions (CONTAINMENT_AND_CRATES Trap 3) | Copy moneycraft's `run_mcp_stdio` |
| GainCraft/BuchCraft/TradeCraft JSON-RPC loops with no `initialize` | Byte-exact probe `initialize -> tools/list -> tools/call` (gate 4) | Same |
| "FastMCP" in Rust docs | FastMCP is Python | Delete |
| egui/eframe 0.27 and 0.29 | `eframe 0.37` | Pin via workspace deps |
| rusqlite 0.31/0.32 | moneycraft uses `0.40` | Pin via workspace deps |
| Single crate per app | L1 `<app>-core` (+ `<app>-store`), L2 `<app>-mcp`, L3 `<app>-app` | Three-tier workspace |
| Handlers returning hardcoded JSON presented as done | Tiered scorecard + explicit `Demo` oracle marked `"vendor": "demo"` | Real logic or labelled demo, never silent |
| `.unwrap()` everywhere | `deny(unwrap_used, expect_used, panic, todo, unimplemented)` | Lint walls |
| Dotted or ad-hoc tool names | Underscore names with app prefix (`money_quote` style), accept dotted alias | `buch_entry_book` etc. |
| English only | i18n standard, `De` mandatory for these apps | `i18n.rs` per core |
| Authors `Storytold Engineering <engineering@storytold.io>` | Fleet-owned; Storytold is upstream we do not speak for | `sandraschi fleet` |
| API keys / SMTP passwords in config | Windows Credential Manager, env var override (splatcraft precedent) | Shared helper |

### 2.2 Real bugs found in the drafts

- **buchcraft**: tax was derived from every split carrying a tax code. If the
  tax split itself carries the code, VAT is double-counted and U30 is wrong.
  Fix: callers book net lines with a tax key; the engine generates the tax
  split. `md5_digest` was actually FNV. Amounts said x10^4, stored cents.
- **taskcraft**: any commit containing "fix" moved an issue to done. Fix:
  explicit keywords with word boundaries (`closes TC-12`, `fixes TC-12`).
- **deskcraft**: `INTEGER UNIQUE NOT NULL AUTOINCREMENT` is invalid SQLite;
  `FETCH 1:*` re-ingested the inbox on every poll; no Message-ID threading.
- **contractcraft**: Typst compile was faked (returned source bytes as PDF);
  Ed25519 seal described as a signature.
- **formcraft**: sentiment hardcoded to 0.85; HMAC "secret" shipped in client JS;
  `Tab` used with `selectable_value` without `PartialEq`.
- **assetcraft**: 3-year IT useful life called "statutory" (it is tax-office
  practice, make it configurable per category); "micro-cents" vs cents.
- **doccraft**: English-only embedding model for German docs; `fetch_document`
  hardcoded.
- **gaincraft**: `tools/call` read the tool name into `account_id` and scored a
  hardcoded account; `regex` used without the dependency.
- **tradecraft**: NYSE RTH hardcoded to 14:30-21:00 UTC (wrong for most of the
  year under US DST, ignores holidays); EUR sizing against a USD account.

### 2.3 Scope corrections

- **TradeCraft is not a new app.** moneycraft v0.7.0 already has `PaperBroker`,
  `BrokerLimits` (max notional, daily loss halt, symbol allowlist) and refuses
  live orders in code. The useful parts of the TradeCraft draft (ATR channel
  breakout with Chandelier exit, the capital reality check, the KESt notes)
  become a moneycraft strategy and a section in moneycraft's docs.
- **ArtifactCraft is out of this suite.** It is fleet infrastructure, not a
  back-office app. Parked as a separate candidate.
- **DocCraft name is taken.** The old Python doccraft was retired today
  (superseded by bookcraft + office-mcp), and the draft overlaps with memops /
  advanced-memory-mcp. See 7.1.

## 3. Shared foundation: `craft-biz`

Nine apps re-implementing ONORM money formatting is how drift starts. One
library crate, sibling to `craft-ai`, path-dependency like moneycraft's use of
`databasecraft-store`:

```text
D:\Dev\repos\craft-biz\crates\craft-biz\src\
  money.rs      Money(i64 cents), EUR only in v1, checked arithmetic, ONORM A 1080 format/parse ("1.250,50")
  at.rs         ATU UID validator with real checksum, IBAN mod-97, Austrian date formats
  deadline.rs   Kuendigungsfrist math: term end, notice months, end-of-quarter/month rules
  ekr.rs        EKR chart seed (classes 0-9, common accounts), tax keys V20/V10/V13/U20/U10/U13/IG
  bus.rs        event envelope + file outbox/inbox/ack (see below)
  secrets.rs    Windows Credential Manager read with env override
  i18n.rs       shared En/De keys (Money, dates, status words)
  mcp.rs        run_mcp_stdio + tools/list helpers, so every app's loop is identical
```

**Integration bus: files, not sockets.** Follows the fleet outbox/inbox/ack
contract (FLEET_DEEP_ANALYSIS_2026-07-13 section 3). An app emits an event by
writing `%LOCALAPPDATA%\craft-biz\bus\<target>\inbox\<ulid>.json`; the target
consumes it only when told (`<app> inbox drain [--json]`, also an MCP tool) and
writes an ack. No daemon, no port, no app depends on another app being installed.

```json
{ "id": "01JC...", "kind": "asset.depreciation_due", "source": "assetcraft",
  "target": "buchcraft", "created": "2026-12-31T23:00:00Z",
  "payload": { "asset_tag": "GOL-001", "year": 2026, "amount_cents": 133333,
               "debit": "7010", "credit": "0700" } }
```

Initial event kinds (the only cross-app links built in v1):

| From | To | Kind | Effect in target |
|---|---|---|---|
| assetcraft | buchcraft | `asset.depreciation_due` | Draft journal entry (not booked until approved) |
| contractcraft | gaincraft | `contract.executed` | Account ARR and cancellation deadline set |
| contractcraft | taskcraft | `contract.deadline` | Issue created with due date |
| deskcraft | taskcraft | `ticket.escalated` | Bug issue linked back to ticket id |
| deskcraft, formcraft | gaincraft | `signal.negative` | Sentiment component updated |
| teamcraft | taskcraft | `capacity.changed` | Sprint capacity note on milestone |

Everything else in the Gemini integration matrices is out of scope until a pilot
user asks for it.

## 4. Per-app specs (improved)

Common to all: repo `D:\Dev\repos\<app>`, crates `<app>-core`, `<app>-store`
(rusqlite WAL, migrations table), `<app>-mcp` (clap CLI, every verb `--json`,
`mcp` subcommand), `<app>-app` (egui 0.37). `--allow-path <DIR>` confinement on
every file-touching verb. Demo vendor seeds a realistic fixture DB with
`<app> demo seed`. Tool names below are MCP names; CLI verbs mirror them
(`buchcraft entry book ...`).

### 4.1 buchcraft (build first: it is the hub)

- **Model:** accounts (EKR), journal entries (Belegkreis AR/ER/BK/KA/SO,
  Belegnummer per year per Kreis), splits (cents, +Soll/-Haben), tax lines
  generated by engine, bank transactions, periods (open/closed).
- **Invariants:** sum of splits = 0 per entry; no UPDATE/DELETE on booked
  entries (SQLite triggers enforce it); corrections only via `entry_reverse`
  (Storno links both ways); closed periods reject bookings.
- **Tools:** `buch_status`, `buch_accounts_list`, `buch_account_add`,
  `buch_entry_book`, `buch_entry_reverse`, `buch_journal_list`,
  `buch_balance` (Saldenliste), `buch_account_ledger` (Kontoblatt),
  `buch_bank_import` (Erste George CSV first, CAMT.053 later),
  `buch_bank_unmatched`, `buch_bank_match`, `buch_u30` (KZ 000/022/029/060/065/070/095
  pre-fill), `buch_period_close`, `buch_export_csv`, `buch_inbox_drain`.
- **Agent flow that sells it:** agent pulls unmatched bank lines, proposes
  account + tax key, human approves in the egui inbox view, engine books.
- **Non-goals v1:** FinanzOnline submission, Registrierkasse/RKSV, payroll,
  balance sheet per UGB format (Saldenliste only), multi-currency.

### 4.2 taskcraft

- **Model:** projects (bound to a repo path), issues (`TC-n` per project),
  milestones, labels, relations with cycle detection on `blocks`, linked commits.
- **Tools:** `task_project_init`, `task_issue_create`, `task_issue_list`,
  `task_issue_show`, `task_issue_update`, `task_issue_move`,
  `task_relation_add`, `task_milestone_*`, `task_git_sync` (git2, explicit
  `closes|fixes|resolves TC-n` only, idempotent), `task_board` (lanes JSON),
  `task_inbox_drain`.
- **Overlap check:** gitops-mcp handles GitHub issues; taskcraft is the local
  tracker. A GitHub import is Phase 3, not v1.

### 4.3 teamcraft (time and leave, not payroll)

- **Model:** employees (non-secret fields only), time entries, breaks, leave
  requests, leave balances per year, KV minimum table (user-imported CSV, no
  hardcoded KV figures, they change every year).
- **AZG engine:** 10h/12h daily, 60h weekly, 48h average over 17 weeks,
  30 min break above 6h, 11h daily rest. Violations are typed, stored and never
  silently corrected. Entries lock after the employee confirms the week.
- **Tools:** `team_employee_add`, `team_employee_list`, `team_clock_in`,
  `team_clock_out`, `team_time_add`, `team_azg_check`, `team_leave_request`,
  `team_leave_decide`, `team_leave_balance`, `team_kv_import`, `team_kv_check`,
  `team_timesheet_export` (AZG section 26 record, CSV/PDF via pdfcraft).
- **Non-goals:** Lohnverrechnung, SV/LSt computation, ELDA. Health data
  (sick-leave reasons) never stored, only day counts.

### 4.4 assetcraft

- **Model:** hardware assets, software licences (seats, allocations), warranty
  and certificate expiries, maintenance log, depreciation schedule rows.
- **AfA engine:** cents, GWG limit configurable (default 1,000 EUR net since
  2023), Halbjahres-AfA, useful life per category (default 3y IT, 5y other,
  editable). Remainder cents go to the final year, never a stray 4th year.
- **Tools:** `asset_add`, `asset_list`, `asset_show`, `asset_dispose`,
  `asset_afa_schedule`, `asset_afa_year` (emits `asset.depreciation_due`),
  `asset_license_add`, `asset_license_assign`, `asset_license_audit`,
  `asset_expiries`, `asset_label` (QR SVG to file).
- **Recombinant hook:** Goliath, the robots and the plugs are real assets;
  an import from rust-devices-mcp / winops inventory gives day-one real data.

### 4.5 contractcraft

- **Model:** templates (variables declared), contracts (status machine
  Draft -> UnderReview -> PendingSignature -> Executed -> Terminated/Expired),
  clauses, redlines, seals, deadlines.
- **Rendering:** wrap, do not reimplement. Markdown/Typst source rendered by the
  `typst` CLI when present, else WordCraft/PdfCraft headless (per the "wrap
  those engines" doctrine). If neither is installed the verb fails with a clear
  error; no fake PDF.
- **Risk rules:** TOML rule file, DE + EN patterns (unbeschraenkte Haftung,
  Schad- und Klagloshaltung, automatische Verlaengerung, Gerichtsstand outside
  AT, missing AVV for personal data). Deterministic; LLM review optional via
  craft-ai-core and always labelled as advisory.
- **Seal:** SHA-256 of rendered bytes + Ed25519 over (contract id, hash,
  timestamp). Documented as tamper evidence, not a signature with legal effect.
  QES (ID Austria / A-Trust) out of scope.
- **Tools:** `contract_template_add`, `contract_template_list`,
  `contract_draft`, `contract_render`, `contract_risk_scan`,
  `contract_redline` (`similar` crate diff), `contract_transition`,
  `contract_seal`, `contract_verify`, `contract_deadlines`, `contract_inbox_drain`.

### 4.6 deskcraft

- **Ingest:** maildir / `.eml` folder first (testable, offline). IMAP only after
  checking whether lookcraft's store can be the source; one mail stack in the
  fleet, not two.
- **Threading:** Message-ID / In-Reply-To / References, subject fallback.
  UID high-water mark per mailbox, never re-ingest.
- **Replies:** written as `.eml` drafts to outbox by default. Sending needs
  `--send` plus configured SMTP credentials from Credential Manager.
- **Tools:** `desk_ingest`, `desk_ticket_list`, `desk_ticket_show`,
  `desk_reply_draft`, `desk_reply_send`, `desk_ticket_update`, `desk_macro_*`,
  `desk_sla_status`, `desk_escalate` (emits `ticket.escalated`).

### 4.7 gaincraft

- **Health score:** the draft formula is fine and stays deterministic
  (adoption 0.45, recency 0.35 with 14-day half-life, sentiment 0.20, weights in
  config). LLM triage is optional and its output is schema-validated and capped
  to a 0.8-1.2 modifier, as the draft intended.
- **ArbVG:** telemetry is imported as per-account daily aggregates only. The
  schema has no per-person column, so the safe path is the only path.
- **Tools:** `gain_account_add`, `gain_account_list`, `gain_telemetry_import`
  (CSV), `gain_health`, `gain_health_all`, `gain_cta_list`, `gain_cta_resolve`,
  `gain_deadlines`, `gain_inbox_drain`.

### 4.8 formcraft

- **Model:** forms (JSON schema of questions + conditions), responses, rollups.
- **Collection:** see decision 7.3. Default proposal: import-first (CSV/JSON
  from any collector) plus an opt-in `formcraft serve --port` with a registered
  port, per-form server-side token, IP truncation, honeypot.
- **Sentiment:** small DE + EN lexicon, labelled as such, with negation
  handling; honest about its limits.
- **Tools:** `form_define`, `form_validate`, `form_list`,
  `form_responses_import`, `form_responses_list`, `form_nps`, `form_report`,
  `form_route_detractors` (emits `signal.negative`).

### 4.9 wikicraft (Gemini draft name: DocCraft)

If kept: Markdown tree is the source of truth, SQLite FTS5 index rebuilt from
it, ADR frontmatter, wiki-link graph. Embeddings via a multilingual model or
skipped in v1 (FTS5 with `unicode61 remove_diacritics` is good enough for a
small firm's wiki). Must not duplicate memops; the honest test is "what does
this do that `adn_knowledge` + bookcraft do not". Current answer: ADR lifecycle
(proposed/accepted/superseded) and a repo-local `docs/` view. That may belong in
codercraft instead of a new app.

## 5. Explicit non-goals (all nine)

- No cloud sync, no multi-user server, no web UI.
- No filing with authorities (FinanzOnline, ELDA, Firmenbuch).
- No qualified signatures, no payroll, no Registrierkasse.
- No live trading (moneycraft keeps its refusal).
- No per-person behavioural telemetry anywhere.

## 6. Phasing (AI-assisted, realistic)

| Phase | Work | Days |
|---|---|---|
| 0 | `craft-biz` crate (money, AT validators, deadline math, EKR seed, bus, secrets, shared MCP loop) with tests; scaffold 8 repos from the moneycraft layout | 1 |
| 1 | Tier 1 per app: core + store + CLI `--json` + MCP stdio + demo seed + tests, 6-gate DoD. Order: buchcraft, taskcraft, teamcraft, assetcraft, contractcraft, deskcraft, gaincraft, formcraft | 6-8 |
| 2 | L3 egui app per repo (one or two real views each, De/En), democraft recipes (3 per app), mcd craft-fleet pages | 4-5 |
| 3 | Bus wiring (6 event kinds), George CSV against a real export, maildir/lookcraft ingest, git2 sync on a real repo, typst/pdfcraft render | 3-4 |

Roughly 2.5-3 weeks for all eight to Tier 2 with basic GUIs. buchcraft alone to
a usable Tier 2 is about 2 days.

**Definition of done per app (Tier 1):** 6 gates from RUST_ARTCRAFT_STANDARD,
plus: every MCP tool has a unit test through `call_tool`, `<app> demo seed`
produces a DB the GUI can open, README states what is demo and what is real,
AGENTS.md (LF, single trunk, no em dashes), start.bat/start.ps1 with instacrash
guard, fleet launcher in `starts/`.

## 7. Decisions (taken 2026-11-09)

1. **DocCraft:** build under a new name. Working name **wikicraft** (rename
   freely before Phase 0). Scope as in 4.9: Markdown tree as source of truth,
   FTS5, ADR lifecycle, link graph; no duplication of memops.
2. **Who builds:** Claude builds all nine, one at a time, in the order of
   section 6. Each app closes the 6-gate DoD before the next starts.
3. **formcraft collection:** import first, plus opt-in `formcraft serve --port`
   on a port registered in WEBAPP_PORTS.md.
4. **Pilot data:** synthetic fixtures only for v1. Consequence, stated not
   hidden: Tier 1/2 verify invariants and Austrian rules against fixtures and
   published examples, not against a live business. Grades stay capped at B
   until real data has gone through buchcraft and teamcraft.
