## 1. What GLM-5.3 Is (Primary-Source Spec)

- Flagship, text-only input, 1M-token context, 128K max output.
- Reasoning ALWAYS enabled. `thinking.type: enabled` only. `reasoning_effort: low | high | max`, default `max`. `disabled` hard-fails — migrate old configs to `enabled + low` before bumping model id to `glm-5.3`.
- Recommended: `max` for coding / long-horizon agents, `low` for cheap triage.
- Same base model as GLM-5.2; all deltas from post-training: environment scaling toward multi-day expert-work tasks (ML infra speedups with cluster access), synthetic runnable long-horizon envs with hidden state, judge-agent solvability checks, oracle/no-op/unsolved-state verifier gates, SAO-with-compaction RL carried over from 5.2.
- Token efficiency claim: Max effort 34.5% at ~75K out-tokens/task vs 5.2 23.4% at 96K; High effort 31.4% at ~50K vs Claude Opus 4.8 29.5% at 120K. Still behind Claude Fable 5 Max 39.5%.

## 2. Power Evidence (Vendor Numbers — Read Critically)

### 2.1 Coding / agents (Z.ai Code Bench + public)

- Z.ai Code Bench (private, contamination-resistant per vendor): +50% over 5.2. No independent reproduction yet.
- Terminal-Bench 3.0: 4.6 -> 28.3. DeepSWE v1.1: 46.2 -> 66.9. Agents Last Exam (CLI): 23.8 -> 28.5.
- SOTA-among-open-source claim on Terminal-Bench 3.0 + Agents Last Exam. Plausible given deltas, but await Artificial Analysis / independent runs.

### 2.2 Cyber — the section that matters for the red-team claim

Z.ai's own framing (docs page, Emergent Cyber Capability):

- Training mix added vuln-discovery data + envs. Surprise: capability scaled faster than expected up the exploitation chain.
- CyberGym (white-box source -> trigger fault): **5.3 = 84.5%**, 5.2 = 77.2%, Mythos 5 = 83.8%, GPT-5.6 Sol = 83.6%. **Best on this benchmark. This is the only place parity/lead vs Mythos holds.**
- ExploitBench (real-vuln reasoning + exploitation): **5.3 = 54.4%**, 5.2 = 24.4% (2x+), Mythos 5 = 78.0%, GPT-5.6 Sol = 76.5%. **Gap still ~24 points.**
- ExploitGym (time-normalized completes): **5.3 = 105 (2h) / 130 (6h)**, 5.2 = 29/39, Mythos 5 = 181/247. **Gap still large.**
- Vendor's own summary: further up the chain = larger gain vs 5.2 AND wider remaining gap to closed frontier.
- Real-world transfer: with Chinese security teams since 5.2, 2436 vulns across 269 projects after dedup/expert review, 1097 med-high, kernels/OS/browser-engines/infra/web/net, oldest ~40 years unnoticed. Ongoing Z.ai Security Disclosure Ledger tracks public vs under-disclosure + CVE + age-in-codebase.

Honest fleet reading:

- "Similar exploit-writing ability to Mythos/Fable" is TRUE for discovery (CyberGym) and FALSE for end-to-end exploitation (ExploitBench/Gym) on vendor's own numbers. Do not collapse the chain.
- "Lack of effective guardrailing" is NOT proven by these benchmarks — they measure capability with guardrails off / in eval harness. Guardrail bypass rate needs a separate jailbreak / refusal benchmark which Z.ai does not publish and the alleged mailing-list analysis has not been independently fetched. Treat as open question, Section 3.
- Dual-use consequence stands regardless: a discovery-parity open model compresses the low end of vuln discovery even if weaponization still lags closed frontier.

## 4. Why the Watershed Thesis Is Plausible Anyway

Even discounted for vendor benchmarks, three structural facts make the R1 comparison serious:

- **Discovery parity in the open.** CyberGym lead means the cheapest stage of the pipeline (find the bug class) is now commoditized. ExploitGym gap matters less to defenders-turned-scanners running at fleet scale.
- **Post-training > pre-training for agents.** 5.3 reuses 5.2 base; gains come from env synthesis + verifier pipelines + SAO-compaction. That recipe replicates to every other open lab (Qwen, DeepSeek, Kimi) within weeks — biweekly cadence doc already tracks this.
- **Distribution is solved.** HF org + `zai-sdk` + OpenAI-compatible endpoints + `coding-helper` one-click loader into OpenCode/Claude/Codex/Crush/Droid. Friction from weights to agent is one `npx`.

Falsifier that would kill the thesis: independent evals show Z.ai Code Bench gains don't transfer off-distribution (e.g., SWE-bench Multilingual flat, Tau3-Banking flat).

## 5. OpenCode Integration (Copy-Paste)

### 5.1 Two lanes — do not mix

| Lane | When | BaseURL | Key |
|---|---|---|---|
| A. Model API pay-per-token | API balance, runtime use, fleet webapps | `https://api.z.ai/api/paas/v4` | `z.ai/manage-apikey/apikey-list` + billing top-up |
| B. Coding Plan subscription | Flat-ish coding in supported tools incl. OpenCode | `https://api.z.ai/api/coding/paas/v4` | `z.ai/subscribe` (Individual / Team) |

Also valid: Anthropic protocol `https://api.z.ai/api/anthropic`, Responses `https://api.z.ai/api/v1`. If previously on Coding Plan incl. expired, currently ONLY the Chat Completions coding endpoint works.

### 5.2 Fastest (interactive)

```powershell
opencode auth login
# select Z.AI            -> lane A
# select Z.AI Coding Plan -> lane B
# paste key
opencode
# inside: /models -> glm-5.3
```

One-click loader alternative:

```powershell
npx @z_ai/coding-helper
# wizard: language -> plan -> key -> pick OpenCode -> load plan -> manage MCP (optional) -> launch
coding-helper doctor   # health check
coding-helper auth glm_coding_plan_global <token>  # non-interactive variant
```

### 5.3 Pinned config (recommended for fleet)

Global `~/.config/opencode/opencode.json` (`%USERPROFILE%\.config\opencode\opencode.json` on Windows). Per-project `./opencode.json` overrides/merges.

Lane B — Coding Plan:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "z-ai-coding-plan": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Z.AI Coding Plan",
      "options": { "baseURL": "https://api.z.ai/api/coding/paas/v4" },
      "models": {
        "glm-5.3": { "name": "GLM 5.3", "limit": { "context": 1000000, "output": 128000 } },
        "glm-5.3-flash": { "name": "GLM 5.3 Flash" },
        "glm-5.3-flashx": { "name": "GLM 5.3 FlashX" }
      }
    }
  },
  "model": "z-ai-coding-plan/glm-5.3",
  "small_model": "z-ai-coding-plan/glm-5.3-flash"
}
```


Verify:

```powershell

```

Raw curl sanity (coding lane):

```powershell
curl -X POST "https://api.z.ai/api/coding/paas/v4/chat/completions" `
  -H "Content-Type: application/json" `
  -H "Authorization: Bearer $env:Z_AI_API_KEY" `
  -d '{"model":"glm-5.3","messages":[{"role":"user","content":"hi"}],"thinking":{"type":"enabled"},"reasoning_effort":"max","max_tokens":100}'
```

Troubleshooting: wrong endpoint = quota not consumed or 401 despite valid key; `thinking.type: disabled` = 400 on 5.3; `Support Images` checked in Cline-like UI = spurious failures (5.3 text-only, use Flash for multimodal); Coding Plan key in unsupported tool = ToS breach, use Model API key instead.

### 5.4 Fleet ON vs IN distinction

- **ON the fleet (dev):** `cd D:\Dev\repos\<repo>; opencode` with above config. Fleet `AGENTS.md` chain + `opencode.json` watcher ignores + `just ci` still apply. GLM-5.3's long-horizon strength fits `assfix` sweeps; keep diffs <=5 files/commit per hard rule.
- **IN the fleet (runtime):** every SOTA webapp exposes Settings LLM (Zustand `store/llm.ts` + `lib/provider.ts`). Add custom OpenAI-compatible provider: BaseURL `https://api.z.ai/api/paas/v4` (runtime lane, NOT coding endpoint), key, model `glm-5.3`. Centralize once in `llm-gateway` / `openrouter-mcp` / `local-llm-mcp` and point satellite webapps at the gateway. Never commit `.env`; keep `.env.example`. Local-first fallback (`ollama/muse-glimmer:30b` etc.) stays per `LOCAL_LLM_FIRST_DOCTRINE.md`.

## 6. Cost Model (Verified Pricing)

Per 1M tokens, USD: 5.3 `$1.4 in / $0.26 cached / $4.4 out`, 5.2 same, Flash `$0.15/$0.03/$0.50`, FlashX `$0.37/$0.075/$1.25`. Cache storage currently limited-time free. Built-in web search `$0.01/use`.

Practice: Flash for Inbox/Logs triage + plan-agent drafts; 5.3/max for build-agent + refactors; weekends + off-peak for batch `assfix` (50% points). Track spend against `TOOLING_COST_MODEL.md` `$1/min` overage cliff on Claude/Antigravity tiers.

## 7. Safety Note for Fleet Operators

Until guardrail analysis is reproduced: treat GLM-5.3 as **dual-use discovery-capable**. Allowed: own-code audit, own-vuln triage, Disclosure-Ledger-style coordinated disclosure, sandbox-only PoC with written authorization. Not allowed: exploit-chain generation against third-party systems, guardrail-stripping prompts, piping subscription quota into unauthorized tools. Log dual-use sessions in `operations/session-log/` per convention.
